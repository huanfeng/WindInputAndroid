## A. 工具栏编辑改拖拽式

现状：快捷面板「编辑工具栏」里点图钉选常驻，「当前顺序」行每项带 ‹ › 两个钮一格一格挪（`QuickPanelWindow.rebuildOrder`）。
挪一个到头要点好几下，且 ‹ › 小、易点错。

目标（照微信「定制工具栏」）：
- 编辑态顶部是**工具栏预览**：常驻项按工具栏上的顺序排成一行（与真工具栏同样的图标），每项右上角 ⊖，点 ⊖ 移除。
  **按住拖动**左右换位（按下即可拖，不必长按；拖动时该项浮起、其余项让位动画），抬手落位即保存。
  不足 `MAX_PINS` 时补虚线空位，空态写「点下面带 ＋ 的功能加到工具栏」。
- 下方网格：能常驻的格子右上角 ＋（未常驻）/ ✓（已常驻，点了移除）；不能常驻的变淡。已满 5 个时 ＋ 变灰，点了提示「工具栏最多 5 个」。
- 快捷面板格子本身的顺序不变（不做网格排序）。
- 纯逻辑（移除 / 加入 / 拖动中按指位算插入位）抽成可 JVM 单测的函数，`ToolbarItem.parse/format` 不变，配置键不变（`ui.android.toolbar_pins`）。
- e2e：现有 [45] 等用例里凡依赖 ‹ › 或图钉的要跟着改；新增「拖动换位」「⊖ 移除」「＋ 加入」「满 5 个拒绝」用例。

状态：已实现。纯逻辑在 `ToolbarPinEdit`（单测 `ToolbarPinEditTest`）；满 5 个时的提示写在编辑提示行里（不弹 Toast）。
原有用例没有依赖 ‹ › / 图钉的，未改；新增 e2e [62] 拖动换位、[63] ⊖ 移除 / ＋ 加入、[64] 满 5 个拒绝 + 工具栏按新顺序摆（`scripts/emu-cases/toolbar-edit.sh`）。

## B. 九宫格左列符号栏重做（只做数字框）

现状：`KeyboardView.drawSide/handleSideTouch` 手画一列，拖动无惯性，按下只换底色；符号写死在
`WindInputImeService.NUMBER_SIDE_SYMBOLS` / `PHONE_SIDE_SYMBOLS`。

目标：
- **惯性滑行**：`VelocityTracker` + `OverScroller.fling`，`computeScroll` 推进；按下时停住滑行（按下一格不触发上屏）。
  到顶 / 到底不回弹（列很短，回弹显乱），可选边缘渐隐提示还能滚。
- **按下效果**：按下格画成与按键同圆角的浮起块（按键按下色 + 轻微放大或强调底），且与按键一样保证至少可见
  `MIN_HIGHLIGHT_MS`（快速点击也看得见）；格间画细分隔线。
- **自定义**：数字框列表可配，键 `ui.android.number_side_symbols`（存法：每项之间用 `\n` 分隔，单项 1–4 个字符，
  允许 `,`）。列最底下固定一格「自定义」（齿轮图标），点开设置页对应二级页。电话框仍用固定的 `PHONE_SIDE_SYMBOLS`，
  也不显示「自定义」格。
- **设置页**：「键盘」页下新二级页「数字键盘符号」：列表每行一个符号，拖动手柄排序、删除；底部「添加」（输入框，
  去空白、重复拒绝、长度校验）、「恢复默认」（确认后写回出厂列表）。空列表允许（列里只剩「自定义」）。
- e2e：现有「* 在左列第 3 项」用例按新列表位置核对；新增「设置里改列表后键盘左列跟着变」「点自定义进设置页」。

状态：已实现。纯逻辑在 `NumberSideSymbols`（单测 `NumberSideSymbolsTest`）；配置串里的换行由 `UserConfig` 转义成 `\n`
（此前基本字符串不转义换行，写出的 TOML 不合法）。左列各格报无障碍节点「左列·<符号>」/「自定义」；换输入框时左列回到顶上。
设置页入口在「键盘布局」页底部；输入法直达二级页走 intent extra（`SettingsActivity.EXTRA_PAGE` / `EXTRA_SUB`）。
未做边缘渐隐。出厂列表与行高不变，[24]「* 在左列第 3 项」无需改。新增 e2e [65] 删除 / 拖动排序后键盘左列跟着变、
[66] 添加（重复拒绝）与恢复默认二次确认、[67] 惯性滑到底点「自定义」直达设置页（`scripts/emu-cases/numpad-side.sh`）。

## C. 退格下滑 = 恢复刚删的内容

调研：Gboard 左滑删词后在候选条给「恢复刚删的词」，2025 年的撤销按钮也是输入法自己记历史，不靠应用的 Ctrl+Z；
国内几家未查到公开资料。故**由输入法自己记最近一次删除**，所有输入框都有效（不发 Ctrl+Z）。

- 手势：`BackspaceGestureMachine` 加「下滑」模式：下滑量 > activate 且大于横向位移时进入，气泡显示「↶ 恢复」，
  下滑过 threshold 抬手 = 恢复；回到 exit 以内 = 反悔。滞回规则与上滑一致。没有可恢复内容时下滑不进入该模式（照旧是单击 / 连删）。
- 记录（Service 侧 `DeleteUndo`，纯逻辑可单测）：只记**输入框里的**删除（有编码时退格删的是编码，不记）。
  - 单删 / 连删：同一次按压里连续删的合成一条；相邻的两次按压之间没有别的输入也合并（「删删删」一次恢复）。
  - 扩选删、删光标前、清空：各记一条，清空记光标前后两段，恢复后光标回原位。
  - 只留**一条**（不做多级撤销），恢复后清掉。上屏 / 输入 / 移光标 / 换输入框（`onStartInput`、`onUpdateSelection` 光标不在记录位置）即作废——
    防止把旧内容插到别处。
- 恢复：`commitText` 放回（清空则先放光标前段，再放后段并把光标移回中间），包在 `beginBatchEdit` 里。
- 面板（编辑面板等）的退格同样接这个手势，接口 `BackspaceGesture.Listener.onRestoreDeleted()` / `canRestoreDeleted()`（默认无）。
- 设置：沿用「退格滑动手势」开关，不另加开关。
- e2e：删几个字 → 下滑恢复；清空 → 下滑恢复且光标在原位；删后打字再下滑不恢复。

状态：已实现。记录逻辑在 `DeleteUndo`（单测 `DeleteUndoTest`），下滑模式在 `BackspaceGestureMachine`（`BackspaceGestureMachineTest` 的「下滑恢复」一组）；
e2e 用例 [68]–[68d]（`scripts/emu-cases/backspace-undo.sh`，含符号页面板退格）。实现要点：
- 单删多是发 KEYCODE_DEL，应用再投递一次才删，删完立刻读光标可能还是删前的位置：此时先挂起，等「旧选区 = 删前选区」的那条
  `onUpdateSelection` 回报再算删了什么（挂起 1 秒没等到就丢）。
- 记录后先等删除自己引起的那条回报（光标到恢复点），之前到的旧回报不管；之后光标离开恢复点即作废。恢复时再同步核对一次光标。
- 密码框（直输）不记，不在内存里留密码片段。
- 没有可恢复内容时下滑不进恢复模式，行为同改动前（主键盘上手指滑出键外抬手 = 什么都不做，不是单击）。
